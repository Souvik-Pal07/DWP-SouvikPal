# DWP Service Desk Triage Summary

## Summary (one line)
Contract specialist reports Copilot gives vague, generic answers about clauses in the contract templates library and does not appear to read the actual documents.

## Impact (who/how many/business urgency)
- Who: Contract specialist working with the firm's contract templates library.
- How many: Single reported user; may reflect a wider issue for anyone querying the same library (to-verify).
- Business urgency: Moderate; Copilot is functional but producing low-quality, unhelpful output, reducing value and trust in the tool (to-verify).

## Known facts
- Ticket reference: T-1005.
- User group/context: Legal – Contract specialist.
- Reported issue: Copilot returns generic answers rather than clause-specific content when asked about documents in the contract templates library.
- Copilot's quality depends on the semantic index having indexed the files and on the user having direct access to them; generic responses often indicate Copilot is answering from general knowledge rather than the actual documents.
- Possible causes: files not indexed (new, recently moved, or in an unsupported file type/location); user lacks direct read permissions so Copilot cannot ground its response; library is too large or documents are image-based PDFs Copilot cannot parse.

## Missing information to gather
- Whether the user can open and read the contract template files manually in SharePoint/OneDrive (to-verify).
- Whether the files are in a supported format (e.g., .docx, text-based .pdf) rather than scanned image PDFs (to-verify).
- Whether the contract templates library is in SharePoint Online and within the Microsoft 365 Copilot semantic index scope (to-verify).
- Whether the files were recently uploaded, moved, or migrated (indexing can take time) (to-verify).
- Whether the user is referencing the files directly in the Copilot prompt (e.g., pasting a link) or asking generically (to-verify).
- Whether sensitivity labels on the files could restrict Copilot grounding (to-verify).
- Whether other users querying the same library experience the same generic responses (to-verify).
- Exact Copilot prompts used and entry point (M365 Chat, Copilot in Word, Copilot in SharePoint) (to-verify).

## Likely category
Copilot semantic index not grounded on the contract templates library — caused by permissions gap, unsupported file format, indexing delay, or incorrect prompting technique (to-verify).

## First diagnostic step
Ask the user to open one specific contract template file directly in SharePoint, then use Copilot in that open document (via the Copilot pane in Word or SharePoint) and ask a specific clause question; if Copilot responds accurately in-document but not from M365 Chat, the issue is index grounding — advise using direct file references in prompts; if it still fails in-document, check whether the file is a scanned PDF or has restrictive sensitivity labels.
